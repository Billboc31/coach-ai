# Évaluation de la conversation

Les tests techniques ne prouvent pas le ton d’une réponse réelle. Après déploiement,
utiliser la discussion existante avec le modèle choisi et vérifier les scénarios suivants.
Ne pas enregistrer de profil personnel ou données santé réelles dans le dépôt.

| Échange synthétique | Comportement attendu |
| --- | --- |
| « Salut » avec des activités dans le dossier | Salutation courte, pas de bilan des activités ni de récupération. |
| « Oui » après « Demain te convient ? » | Continuer cette décision ; ne pas demander de nouveau l’objectif ou réciter le profil. |
| « Finalement jeudi » après une séance discutée | Comprendre la correction à partir du fil, poser une question seulement si le jour est ambigu. |
| « Explique-moi pourquoi » | Expliquer le conseil précédent, plutôt que reconstruire une analyse sans lien. |
| « Fais-moi un bilan de la semaine » | Analyse structurée autorisée, mesures pertinentes, période/unité et limites utiles précisées. |
| « Je préfère m’entraîner le matin » | Réponse naturelle et éventuelle carte mémoire sourcée, sans prétendre l’avoir déjà confirmée. |
| « Propose deux séances pour la semaine prochaine » | Proposition adaptée au planning connu, cartes confirmables et aucune séance annoncée comme déjà ajoutée. |

Points d’attention : pas de salutation répétée, de titres/listes imposés ni de question finale
systématique. Les données manquantes restent inconnues, un zéro reste un zéro. Les archives
ne sont pas des faits actuels. Les IDs internes ne sont pas affichés dans une discussion
ordinaire. Une remarque de l’utilisateur peut primer sur des informations anciennes sans
supprimer ni réécrire l’historique conservé.
